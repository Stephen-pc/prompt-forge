# 网页 / 代码提示词模板库

适用：让 AI 生成网页、组件、脚本、小工具、API 服务。

---

## 一、核心原则：代码提示词是「约束」不是「许愿」

图像提示词写得好不好，结果是「像不像」；代码提示词写得好不好，结果是「跑不跑得起来」。

所以代码类提示词的重点不是形容词，而是**边界条件**：技术栈、输入输出、错误处理、不能动的东西。

---

## 二、七维速查

| # | 维度 | 该填什么 | 漏了会怎样 |
|---|---|---|---|
| 1 | 目标 | 一句话说清做什么、给谁用 | 做出来不是你想要的 |
| 2 | 技术栈 | 语言/框架/版本/依赖限制 | 用了你没装的东西 |
| 3 | 结构 | 文件划分、模块职责 | 全塞一个文件，没法维护 |
| 4 | 数据 | 输入格式、输出格式、数据结构 | 接口对不上 |
| 5 | 交互/流程 | 用户操作路径、状态变化 | 少了关键分支 |
| 6 | 视觉规范 | 配色、字体、间距、响应式断点 | 丑且不一致 |
| 7 | 边界条件 | 错误处理、空状态、超时、上限 | 一遇到异常就崩 |

**第 2 和第 7 是最常漏的两项**，也是返工率最高的两项。

## 三、模板

### 3.1 单页网页 / 小工具

```
【目标】做一个{功能}的单页工具，给{谁}用，解决{什么问题}。
【技术栈】纯 HTML + CSS + 原生 JS，单文件，零外部依赖，不用框架、不用 CDN。
【结构】单个 index.html，内联 style 与 script。
【数据】输入：{形式}；输出：{形式}；不持久化 / 存 localStorage（键名 {key}）。
【交互】
  1. 用户{操作} → {结果}
  2. 用户{操作} → {结果}
  3. 出错时显示{提示}，不弹 alert
【视觉】深色背景 #{hex}，主色 #{hex}，正文 {14}px，圆角 {8}px，最大宽度 {960}px，移动端单列。
【边界】
  - 空输入时按钮禁用
  - 超长文本截断，不撑破布局
  - 复制失败时降级为选中文本
【不要】不要引入任何第三方库；不要用 alert/confirm；不要写注释以外的多余说明。
```

### 3.2 React 组件

```
【目标】实现 {组件名}，用于 {场景}。
【技术栈】React {18} + TypeScript + {样式方案}，不引入额外 UI 库。
【Props】
  - {prop}: {类型} — {含义}，默认 {值}
  - {prop}: {类型} — {含义}，必填
【状态】内部维护 {state}，变化时触发 {回调}。
【行为】
  - 点击 {元素} → {行为}
  - {条件} 时禁用并降低透明度
【可访问性】键盘可达，focus 可见，aria-label 齐全。
【边界】空数据渲染骨架屏；加载中禁用交互；错误时展示重试按钮。
【输出】只给组件文件，类型定义内联，不写示例页。
```

### 3.3 脚本 / 自动化

```
【目标】写一个脚本，{输入} → {输出}。
【环境】{Python 3.12 / Node 22}，只用标准库，不装第三方包。
【输入】{路径/格式/编码}，字段为 {a, b, c}。
【处理】{步骤 1}；{步骤 2}；{步骤 3}。
【输出】写到 {路径}，格式 {csv/json}，编码 UTF-8。
【边界】
  - 文件不存在：打印明确错误并退出码 1
  - 单行解析失败：跳过并记录到 {日志}，不中断整体
  - 大文件：流式读取，不整体载入内存
【要求】函数拆分，每个函数有 docstring；主流程可被 import 复用。
```

### 3.4 API 服务

```
【目标】实现 {资源} 的 CRUD 接口。
【技术栈】{框架} + {数据库}，不使用 ORM。
【接口】
  - GET /{资源}?page=&size= → {结构}
  - POST /{资源} body {字段} → 201 + {结构}
  - 错误统一返回 {code, message}
【校验】{字段} 必填、{字段} 长度上限、{字段} 枚举取值。
【边界】分页 size 上限 100；并发写加锁；超时 5s 返回 504。
【不要】不要打印敏感字段；不要吞异常。
```

## 四、追加约束的常用句式

- 「不要引入任何第三方依赖」
- 「只修改 {文件}，不要动其他文件」
- 「先给我方案和文件清单，我确认后再写代码」
- 「保持现有代码风格，不要重构无关部分」
- 「如果需求有歧义，先列出你的假设，再动手」
- 「给出最小可运行版本，不要过度设计」
- 「写完自查：能否直接运行，缺什么依赖，怎么启动」

最后一条特别有用——它会让模型自己把「跑不起来」的问题暴露出来。

---

## 五、避坑清单

1. **不写技术栈** → 模型默认给你一套你没装的东西，或者混用两个框架。
2. **不写边界** → 正常路径能跑，一输入空值就崩。
3. **一次要太多** → 「做一个完整的电商系统」= 得到一个跑不起来的骨架。拆成三次：先列表页，再详情页，再购物车。
4. **不说「只改这个文件」** → 模型顺手重构了半个项目，diff 没法看。
5. **不给验收标准** → 你不知道它算不算做完了。补一句「验收标准：{具体可验证的行为}」。
